# XPeach 模型路由与令牌验证

[English](guide.md) | 中文

## 变更

后台模型同步保留已有会话的模型选择。模型不可用时，需要显式选择有效路由；同步不再将该会话改到其他模型或账号。显式切换分组只协调 XPeach 的模型选择。

所选提供方必须包含所选模型。通用适配器不再从其他 XPeach 提供方借用同名模型。模型缺失时返回现有的 `UNKNOWN_MODEL` 失败。

分组更新必须在写入前成功验证密钥。验证结果不可用时，不再凭缓存的令牌元数据授权写入。身份查询未完成时，不会把更宽的模型目录作为同步成功结果发布。

管理访问令牌与控制台备用登录都要求完整分页，仅复用与活动密钥确认匹配的令牌；归属未知时禁止创建。没有活动密钥时，新建唯一名称的令牌，由唯一新增 id 和成功的 reveal 确认后绑定。只有管理访问令牌路径为本次新建行设置默认组，既有分组保持不变。密钥槽位在提交前要求用量响应为有效 JSON 且字段类型正确。凭据引用发布失败时，已验证的新密钥可能已提交，依赖请求会被阻止，直到引用一致。

Relay 密钥与令牌身份在 `xpeach.relay.json` 中使用同一修订。共享 profile 使用 `~/.xph/xpeach.relay.json`；隔离的密钥目录可以使用自己的状态文件。该文件存在后，`xpeach.key` 与 `xpeach.token` 只是兼容投影，不能覆盖权威状态。投影未完成时，依赖操作会被阻止，直到启动修复成功。

## 迁移

已有非空 profile 补丁会保留。请在其 `llm-pi-ai` 条目的 `inject` 中追加 `xpeachAccount`，保留其他依赖；这样账号初始化或凭据修复失败时，模型提供方不会激活。新版产品模板已包含此声明。

1. 使用共享凭据启动升级后的进程前，先关闭旧版本。将 `xpeach.relay.json` 随账号数据一同保留；通过账号绑定操作修改凭据，不手工替换其兼容文件。如果启动无法修复未完成的投影，请解决路径或写权限故障后重启。
2. 如果已有会话在同步后提示模型不可用，请在模型选择器中选择可用的提供方和模型，或更新 SDK 客户端明确指定的 provider/model 值。所选提供方应对应预期账号和协议。
3. 如果分组更新无法验证令牌，请检查当前凭据与管理访问权限后重试。修改分组前，确认显示的绑定令牌就是目标令牌。
4. 同步模型并确认已有会话保留原选择。显式选择后，确认下一次请求使用所选提供方和模型。
5. 没有活动密钥时绑定会新增站点令牌，请另行检查旧令牌。创建或绑定报告结果不确定时，重试前先查看站点令牌列表。凭据引用发布失败后，请重启或完成一次成功的模型同步；不要假定已提交的密钥被回滚。
