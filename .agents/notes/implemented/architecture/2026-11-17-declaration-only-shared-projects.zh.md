# Agent Note: 仅生成声明的共享项目

Status: implemented

[English](2026-11-17-declaration-only-shared-projects.md) | 中文

## 问题

生成的 Remote 声明可能引用拆分包经源码映射的 DTO，而不导入其浏览器实现。缺少被引用的声明所属项目时，干净的 Client 编译可能在原源码旁输出这些导入文件。增量构建可能因保留足够产物而掩盖这项缺失。改为引用浏览器实现则可能通过应用 Remote 门面形成循环。

## 决策

拆分包可提供 `tsconfig.shared.json` 拥有纯共享类型。该项目为 composite、仅生成声明，显式声明源码与输出目录，且输出位于 `src` 之外。非空文件集须位于本包源码目录内。顶层源码仅允许接口、类型别名、仅类型导入导出或空模块导出；拒绝运行时值及副作用导入。

两面及生成声明的消费方引用这个共享叶。每个源文件仅有一个声明所属项目；Host 与 Client 叶引用它，不再重复列入该源码。共享项目可以引用中立依赖或其他已验证共享项目，不得进入拆分包的 Host、Client 或 solution 根。workspace constraints 检查这些要求，并为其他引用保留原有的匹配面规则。

## 考虑过的替代方案

**Client 引用 Host 叶。** 能找到 DTO 产物，但会接纳相反编译面；原有隔离规则继续适用。

**引用完整 Client 叶。** 应用 Remote 门面与 Trajectory 浏览器实现已有相互依赖，会形成编译循环。

**在 `src` 保留编译声明。** 会让生成产物承担源码所有权，并掩盖缺失的项目引用。格式化或排除这个文件不能修复其生产方。

## 影响

DTO 源码别名与包导出保持不变。纯共享声明只向 `lib/types` 编译一次；运行时打包仍使用既有 Host 与 Client 入口。强制 Client 编译及其输出文件清单验证源码旁没有生成声明或 JavaScript。项目引用变更仍需干净 CI 构建提供证据。
